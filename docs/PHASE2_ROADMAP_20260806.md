# 2차 구현 로드맵 — 시간을 무기로 (2026-08-06)

1차 구현이 닫혔다. 결산과 함께, "개인이 기관 퀀트를 이길 수 있는 축"을
우리 데이터가 가리키는 방향으로 정의하고 2차 작업을 우선순위로 배열한다.

---

## 1. 1차 결산 (2026-07-21 ~ 08-05)

### 확정된 것 (전부 5폴드 + 사전등록 게이트)

| 항목 | 판정 | 근거 |
|---|---|---|
| 청산: **D+15 단일** | **채택·운영중** | 사다리 −0.17 → D+15 +0.86, 최악폴드까지 완승 |
| 사다리 / TP+5% / SL 전 변형 | 기각 | SL 은 5폴드 중 4폴드에서 최악폴드 악화 |

| 배분조절 K=+0.3 | 유지 (마진 얇음) | 5폴드 0.91>0.86 — 2폴드 "부호반대" 철회 |

### 운영 인프라

- 페이퍼 9북: 챔프(D+15·0.28스케일·KRX500EW 헤지) + 섀도우 8종, 코호트별 정책·지수 태그
- 판정 자동화: 스터디 `--json` → `verdict.py` 사전등록 게이트 → 결론 10줄
- 4090 큐 멱등화, 스모크 진단, launchd 함정 문서화, 백업·수집 견고화

### 메타 교훈 (2차의 헌법)

1. **2폴드는 방향조차 못 정한다.** SL·배분조절·변동성×보유 셋 다 5폴드에서 뒤집혔다.
   단조성도, 4개 조합 일관성도 뒤집힘을 막지 못했다.
2. **폴드 일관성이 진짜 게이트다.** 살아남은 유일한 후보(랭크청산)만 5/5 였다.
3. **서술적 표는 규칙으로 전이되지 않는다.** adaptive 2×2 = +0.00.
4. **MSE ≠ 랭킹 ≠ 알파.** 수급 예측 사건에서 3단이 각각 갈렸다.
5. **변형 표로 데이터를 진단하지 마라.** "r3 죽음"은 epc 한정이었다.

## 2. 테제 — 우리 알파는 느린 알파다

1차 결과가 일관되게 가리키는 사실:

- **보유 4.2일(사다리)에서 알파가 음수, 15일에서 양수, 랭크 기반 ~8.4일 지능형 보유가 최고.**
- 이긴 종목을 일찍 자르는 개입(TP)은 최악, 보유 중 가격 개입(SL)은 무익.
- h1(하루 뒤) 신호는 폴드 간 요동으로 기각 — **일 단위 지평에서 우리 신호는 노이즈다.**
- 수급 추종(단기 정보 소비)은 음수 — 빠른 정보 게임에서 우리는 진다.

즉 **우리 알파는 2~4주에 걸쳐 실현되는 느린 알파**이고, 그 지평은 기관 퀀트가
구조적으로 약한 곳이다: 그들은 용량 제약·환매 압박·월간 성과평가 때문에 빠른
지평에 군집하고, 빠른 지평은 그래서 가장 경쟁이 치열하다. 개인은 반대다 —
소자본(용량 무제한), 무환매(강제청산 없음), 무평가(드로다운 인내 가능).

**시간은 세 가지 형태의 무기가 된다:**

| 무기 | 뜻 | 기관이 못 하는 이유 |
|---|---|---|
| **보유 시간** | 느린 알파를 끝까지 수확 | 환매·성과압박이 조기청산을 강제 |
| **검증 시간** | 실측 A/B 를 몇 주든 돌려 판정 | 기회비용·조직압박으로 승급을 서두름 |
| **데이터 시간** | 지나가는 매달이 새 OOS 폴드가 됨 | 우리도 그들도 공평하나, 우리는 PIT 인프라가 이미 있고 잃을 게 없음 |

## 3. 2차 로드맵

### P0 — 시간을 판정자로 만들기 (이번 주, CPU만)

**3-1. `live_verdict.py` — 실측 판정 자동화.**
`verdict.py` 가 백테스트 게이트를 자동화했듯, **실측 북 비교를 자동화**한다.
매칭 코호트(챔프 · 중기D+15 · 랭크청산, 같은 진입·같은 예산)가 마감될 때마다
실현 순손익을 짝지어 집계하고, 사전등록 임계(코호트 수 N≥15, 짝지은 우세,
NW-t)를 넘으면 "승급 권고"를 자동 출력. **2026-08-11 첫 데이터가 들어온다.**

**3-2. 비용 실측 파이프라인.**
§8-9 의 "실측 비용"을 채우는 것이 랭크청산 승급의 유일한 관문이다.
`attach_live_quotes_to_shadow.py`(이미 존재)를 저녁 체인에 편입해 청산 시점
호가 스냅샷을 축적 → 실효 스프레드를 41bp 가정과 대조. 랭크청산은 회전이
1.8배라 이 숫자가 승급을 결정한다.

**3-3. ntfy 설정.** 무인 운영의 마지막 구멍. 체인이 조용히 죽으면
"시간 무기"가 조용히 꺼진다.

### P1 — 랭크청산 승급 결정 (8/11 + 2~3주)

사전등록해 둔다: **매칭 코호트 15개 이상 마감 + 실측 비용 반영 후에도
랭크청산이 챔프(D+15)를 짝지은 비교에서 이기면 챔프 교체.**
비용이 41bp 를 크게 넘으면 백테스트 우위(+0.58 Sharpe)가 깎이는 속도를
실측으로 계산해 판정. 이것이 1차에서 만든 규율(백테스트→섀도우→실측→승급)의
첫 완주가 된다.

### P2 — 보유를 더 지능적으로: 밴드 리밸런싱 프로토타입 (CPU 스터디 먼저)

랭크청산의 자연스러운 일반화. 현재는 일별 코호트가 병렬로 살아가는 구조인데,
**연속 포트폴리오 + 무거래 밴드**로 바꾸면 회전이 더 준다:

- 목표 보유 = 스코어 상위 10%, **보유 유지 밴드 = 상위 20%** (히스테리시스 그대로)
- 이미 보유한 종목은 밴드 안이면 거래 0. 밴드 밖으로 나가야만 매도, 새로 상위
  10% 에 들어야만 매수. 가중 이탈도 밴드(±x%) 안이면 방치.
- 고전적 무거래영역(no-trade band) 정책 — 거래비용 문헌의 표준 해법이고,
  Buy-Hold-Spread 의 완전형이다.

먼저 기존 예측으로 CPU 백테스트(`band_portfolio_study.py`), 5폴드 + 3중 게이트
통과 시 섀도우 북 10호로. **회전이 낮을수록 비용 민감도가 낮아져 실주문 전환
때 살아남을 확률이 올라간다** — 시간 무기의 직접 구현이다.

### P3 — 용량 해자 정량화 (CPU 스터디)

"기관이 못 들어오는 구간에서 우리 알파가 사는가"를 직접 잰다:
**유동성 버킷 × 보유기간**으로 알파를 분해(`liquidity_capacity_study.py`).
픽의 `current_value_ma20_log` 가 이미 예측 CSV 에 있어 재료는 준비돼 있다.
알파가 저유동성 구간에 몰려 있으면 — 그게 우리 해자의 정량 증거이고,
자본이 커졌을 때의 용량 한계도 같은 표에서 나온다.

### P4 — 모델 축 (다음 GPU 세션)

1. **`fr_s` 수급 랭킹 손실** — 구현·3게이트 완료, `FR=1` 로 실행만 남음.
2. **시드 확장** hz/epc… 는 기각됐으니 ens_s 6시드 유지 + fr_s 통과 시 6시드 확장.
3. **r6 폴드 준비** — train_end 2025-09-05 이후 데이터가 이미 11개월 쌓였다.
   분기마다 폴드를 하나씩 늘리는 재학습 캠페인을 정례화하면, **지나가는 시간이
   자동으로 검증 용량이 된다.** 6폴드 게이트는 5폴드보다 또 강하다.

### 하지 않을 것 (해자 방어)

- **단기 지평 진입 금지.** h1 기각·사다리 기각이 이미 답했다. 속도는 기관의 홈그라운드다.
- **게이트 없는 복잡화 금지.** epc·hz 의 교훈. 새 손실·새 헤드는 3게이트 사전등록 후에만.
- **저녁 체인 의존성 0 유지.** brew·외부 API 를 운영 경로에 넣지 않는다.
- **2폴드로 방향 발언 금지.** 문서에 적을 때도 "2폴드 한정" 을 붙인다.

## 4. 순서 요약

```
이번 주      P0: live_verdict + 비용실측 편입 + ntfy
8/11~       P1: 첫 실측 대조 → 랭크청산 승급 판정 (2~3주 축적)
병행(CPU)   P2: 밴드 리밸런싱 스터디 → 통과 시 섀도우 10호
병행(CPU)   P3: 용량 해자 정량화
다음 GPU    P4: fr_s 실행 → 통과 시 시드 확장, r6 캠페인 정례화
```

1차가 "무엇이 이기는가"를 확정했다면, 2차는 **이기는 것을 실측으로 승급시키는
기계**와 **시간이 지날수록 강해지는 구조**(낮은 회전·자라는 폴드·용량 해자)를
만든다.
