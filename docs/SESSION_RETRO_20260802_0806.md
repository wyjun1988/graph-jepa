## 4. ⚠️ 구조적 약점 — 보충이 필요한 곳

### 4-1. 실측이 사실상 0이다 (가장 큰 구멍)

모든 판정이 **백테스트**다. 실주문은 여전히 0이고, 페이퍼조차 매칭 비교가 안 됐다.

- 랭크청산 규칙 적용 시작 **8/3**, 물타기·결합 **8/7**
- 깨끗한 4-way 매칭 비교는 **8/7 이후 진입분**이 D+15 를 채우는 **8월 말**부터
- 그전 코호트는 "규칙 없이 들고만 있던" 것이라 판정 근거가 아니다

**보충 필요:** 실측 판정기(`live_verdict.py`)가 아직 없다. 백테스트는
`verdict.py` 로 자동화됐는데 실측은 수동이다.

### 4-2. 비용 41bp 가 전부 추정이다

`ARCHITECTURE_VERDICTS §8-9`: "실주문 0이라 41~108bp 전부 추정. **실측 비용 없이
운영 청산구조 변경 금지.**"

- D+15 전환은 회전을 줄이는 방향이라 저촉되지 않았다
- **랭크청산·물타기·결합은 전부 회전/매수횟수를 늘리는 방향**이라 정면 적용된다
- 41bp 가 실제로 60bp 라면 랭크청산 우위(+0.58)가 얼마나 깎이는지 **모른다**

**보충 필요:** 실효 스프레드 실측. `attach_live_quotes_to_shadow.py` 가 이미
있는데 저녁 체인에 안 붙어 있다.

### 4-3. 5폴드는 4090 의존이고, 폴드가 5개뿐이다

- 로컬에 r1~r3 예측이 없어 **5폴드 판정을 로컬에서 못 한다**
- 4090 은 파일 반출 불가 + 간헐 가동. 8/3 세션에서 hz 30런이 통째로 날아갔다
- 폴드 5개 × 시드 3~6개는 **표본이 얇다**. 이번에만 2폴드→5폴드 역전이 3건

**보충 필요:** r6 폴드 추가(train_end 이후 11개월 데이터가 쌓여 있다).
분기마다 폴드를 늘리면 지나가는 시간이 검증 용량이 된다.

### 4-4. 사전등록이 사람 손에 의존한다

`verdict.py` 의 `PREREG` 라벨을 사람이 손으로 적는다. **라벨 불일치가 두 번** 났고,
둘 다 "판정불가"로 조용히 넘어갔다. 만약 다른 정책 라벨과 우연히 맞았다면
**엉뚱한 행을 주판정으로 읽었을 것이다.**

**보충 필요:** 스터디가 자기 주판정 라벨을 JSON 에 함께 뱉고 판정기가
그것과 대조하는 구조.
