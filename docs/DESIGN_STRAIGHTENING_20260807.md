# 잠재 직선화 (Temporal Straightening) — 설계·사전등록

**2026-08-07 작성. 학습 전에 등록한다 — 결과를 보고 게이트를 고치면 사후조정이다.**

원 논문: Wang et al., *Temporal Straightening for Predictive Representations*
(ICML 2026). JEPA 계열에서 **관측 프레임의 인코더 잠재**를 직선화하면 예측이
쉬워진다는 주장. 우리는 적용 지점을 바꿔 쓴다 — 아래 §2.

---

## 1. 무엇을 하는가

궤적 `z_0 → z_1 → … → z_K` 의 **속도** `v_k = z_{k+1} − z_k` 가 방향을 자주
꺾지 않도록 벌점을 준다.

```
L_curv = mean_k mean_node ( 1 − cos(v_k, v_{k+1}) )
총손실 += λ · L_curv
```

- 완전 직선 → 0, 직교 → 1, 완전 역행 → 2 (구현 검증 §5)
- **새 파라미터 0개.** 손실 항 하나뿐이라 체크포인트 구조가 안 바뀐다
- `λ = 0` 이 기본 → 기존 학습·기존 체크포인트에 대해 **완전 no-op**

## 2. 우리는 적용 지점을 옮겼다 (원 논문과 다른 부분)

논문은 **관측 프레임의 인코더 잠재**를 직선화한다. 우리 약점은 거기가 아니다.

- 신호는 `rollout_latent(steps=10)` — **예측기의 다단 롤아웃**에서 나온다
- `hz`(h15/h20 헤드)가 실패한 지점도 **외삽**이었다
- 인코더 잠재를 펴도 롤아웃 경로가 휘면 지평 10에서 무너지는 건 그대로다

→ **예측기가 굴려낸 롤아웃 궤적** `[z_ctx, z_1, …, z_K]` 에 벌점을 건다.

트레이드오프가 하나 있다: 잠재 예측 손실이 `z_k` 를 교사 타깃에 붙들고 있으므로
직선화는 **적합도와 경쟁한다**. λ 가 그 저울이다. 이래서 λ 스윕이 필요하다.

## 3. 배선 (두 경로 전부)

| 경로 | 궤적 수집 방식 |
|---|---|
| `temporal_loss` | `rollout_latent` 를 수동 전개해 각 스텝을 모음 |
| `temporal_multi_loss` | 기존 스텝 루프에 `rollout_trajectory.append(z_pred)` |

**둘 다 건드린 이유:** 한쪽만 배선하면 설정에 따라 조용히 no-op 이 된다.
이 프로젝트에서 "조용히 나빠지는 버그"에 두 번 물렸다
(`SESSION_RETRO_20260802_0806.md` §3-1, §3-4).

곡률 항은 **점 3개(속도 2개)** 부터 생긴다. `rollout_steps=10` → 궤적 11점 →
곡률 항 9개.

CLI:

```
--latent-straightening-weight 0.1
```

4090 큐:

```bash
TS=1 bash scripts/4090_all.sh          # λ=0.1 (기본)
TS=1 TS_W=0.05 bash scripts/4090_all.sh
```

λ=0.1 이 게이트를 통과하지 못하면 다른 λ 가 통과해도 **'승급'까지만** 인정한다.

## 6. 왜 해볼 만한가 / 왜 안 될 수도 있는가

**해볼 만한 이유**
- 파라미터 0개 추가. 실패해도 λ=0 으로 되돌리면 끝이다
- 우리가 실제로 쓰는 경로(10스텝 롤아웃)를 직접 정규화한다
- 지금까지 살아남은 개선은 전부 **모델 스코어를 쓰는 쪽**이었다 (`SESSION_RETRO` §5)

**안 될 수도 있는 이유**
- 주가 잠재가 정말 직선이어야 할 근거가 없다. 추세 반전이 잦은 구간에서는
  **꺾이는 것이 정답**일 수 있고, 그때 직선화는 신호를 뭉갠다
- 적합도와 경쟁한다(§2). λ 가 크면 교사 타깃을 놓친다
- `epc_s`(랭킹 압력 손실)도 "그럴듯한 보조 손실"이었고 기각됐다.
  **보조 손실이 IC 를 밀어올린 전례가 아직 없다**

세 번째가 제일 무겁다. 이건 검정이지 개선이 아니다.
